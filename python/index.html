🎯 从入门到精通：怎么用这个站

1
读一章（30 分钟）
重点不是背语法，是能回答一句话：「这段代码里的用户输入，最后流到了哪里？」——这就是审计的思维方式。
2
做题（15 分钟）
错题会自动进错题本。错在哪，就说明哪个概念只是"看着懂"。
3
动手（30 分钟）
去「实验」页跑一遍当阶段实验，再去「审计靶场」把同一段代码审一遍、看答案对照。只看不练，永远停在「好像懂了」。
4
查手册（随时）
函数记不住查「速查」；名词忘了查「术语」；卡住了看「案例」里的推理过程。
精通判据：不是「背得出函数名」，而是给你一段陌生代码，你能标出输入点、找出危险函数、追出数据流、判断漏洞是否成立，并说出修复方式。首页底部的自测清单就是这张判据表。

🧪 实验与靶场

环境准备（比 PHP 简单，本机就能跑）

1
你的 Python 已经装好了
本机装了 Python 3.14。但注意：直接敲 python 会跳到微软商店（那是 Windows 的占位符），要用 py 命令：py --version。第 2 章会教你把这个理顺。
2
建一个虚拟环境（Python 的必备习惯）
py -m venv .venv 然后 .venv\Scripts\activate。以后所有实验都在这个环境里装包、跑代码，不会污染系统 Python。第 5 章专门讲这个。
3
跑代码
py 文件名.py 就能跑。建议装 VS Code（免费、轻量），装个 Python 扩展就有补全和调试。想做 Web 实验就 pip install flask。
4
不需要虚拟机、不需要 Web 服务器
Python 是脚本语言，本机直接跑。审计类和漏洞类的示例（第 15-20 章）就在你自己的虚拟环境里跑——涉及 Web 的那几个用 flask run --debug 起个本地服务即可（而且「debug 模式」本身就是课程里的一个漏洞点）。
5
两条注意事项
① 有漏洞的示例只在自己电脑上跑；
② 千万不要把这些示例部署到公网服务器——那等于把靶机挂在网上。
红线：第 15-20 章会讲到命令注入、代码执行、反序列化、SSTI。这些演示只允许在你自己的电脑 / 自己的虚拟环境里运行。禁止对任何真实网站、学校系统、公司服务器做测试——无论出于什么目的、无论是否造成损失。学攻击原理是为了写出打不动的代码，这条线不能越。

code 文件夹：可运行的示例（每个都是「漏洞版 + 安全版」对照）

在虚拟环境里直接用 py 文件名.py 跑；Web 类示例用 flask run 起本地服务。每个文件顶部都写了「怎么跑、应该看到什么」。

推荐用法：先用漏洞版打一遍（看现象）→ 切到修复版打同样的 payload（确认失效）→ 打开源码对照。这个「打 → 切 → 再打 → 看源码」的循环，就是第 18 章四步法的实操版。
这一页是「审计靶场」：里面是一段段待审计的 Python 代码，每段都刻意埋了 1-3 个问题。用法：先自己读一遍、写下判断，再展开答案对照。

为什么用这种方式——Python 的安全问题大多不在语法里，而在「这段代码把用户输入交给了谁」。这页每一段都在训练这个判断，正好配合第 15 章的审计方法论。建议学完第 15 章后，每读一段都先标出「输入点」和「危险函数」再往下看。
